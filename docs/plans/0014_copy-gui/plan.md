# 0014: コピーGUIの構築

作成日: 2026-09-13

更新日: 2026-09-13

状態: 未着手

## 目的

運用が安定したコピー経路を、ターミナルを開かずmacOS上からワンクリックで実行できるGUIを構築する。GUIは細かな設定を編集するためのものではなく、既存のプロファイルと共通処理APIを使って日常の取り込みを開始し、実行中であることと最終結果を明確に確認するための薄い操作層とする。

GUIにはPySide6を採用する。macOSのアプリケーションとしてFinderまたはDockから起動できる形にし、CLIとGUIでコピー、検証、安全判定、ログの意味が分岐しない構成を保つ。

## 背景

- 0006でコピー処理をCLIから分離し、`execute_copy()`と構造化結果を実装した。
- 0009で、日常の通常経路は`sd-to-ubuntu`プロファイルを指定する1コマンドに確定した。他の経路もプロファイルとして設定済みである。
- 0009の実機確認では、1,005件・27 GBの取り込みに中断からの再開を含め約7分、全件が既存一致となる再実行に約5分半かかった。GUIは長時間処理中も応答を保ち、処理が継続していることを表示する必要がある。
- 現在はプロファイル解決、転送準備、ログ保存、利用者向けの成功判定の一部がCLI層に残っている。また、共通処理APIは完了結果を返すが、処理中の進捗を通知しない。GUI追加時に、CLIと共有すべき処理の境界を整理する必要がある。

## 設計方針

### 1. GUIは日常操作に限定する

通常利用では既定の日常プロファイルから取り込みを開始する操作を中心とする。コピー元、保存先、転送方式、ホスト設定などの定型値は既存のプロファイル設定を正本とし、GUI上に汎用的な設定編集画面を設けない。

GUIから任意の保存先や転送コマンドを組み立てる機能は持たせない。通常経路以外の既存プロファイルをどのように選択可能にするか、実行前に何を表示するかなどの細かな画面設計は、プラン実行時に決定する。

### 2. PySide6を採用する

GUIツールキットにはPySide6を使う。Pythonの共通処理APIを同一プロセスから利用でき、長時間処理をGUIのイベント処理から分離できること、結果や例外を構造化して表示できること、macOSの`.app`として構築できることを採用理由とする。

PySide6はCLIだけを利用する環境へ不要な依存を持ち込まないよう、GUI用の依存として分離する。採用バージョン、ウィジェット構成、バックグラウンド実行方式、`.app`の具体的な構築設定は、実装時に互換性と実機動作を確認して決定する。

### 3. CLIとGUIで同じアプリケーション処理を使う

GUIからCLIを子プロセスとして起動して標準出力を解析する構成にはせず、共通処理APIを直接利用する。現在CLIに残るプロファイル解決、転送準備、ログ保存、結果判定のうち共通化すべきものを整理し、CLIとGUIの双方から呼び出せる形へ移す。

共通化後もCLIの既存の引数、終了コード、要約、JSONログとの互換性を維持する。GUI固有の表示やmacOS固有の起動処理は共通APIへ混在させない。

### 4. 進捗と結果を安全判断に使える形で表示する

GUIは少なくとも、処理開始前、実行中、正常完了、例外を含む完了、実行不能を区別する。長時間処理では現在の工程と進行が分かる情報を表示し、ウィンドウが無応答に見えないようにする。

コピー済み、既存一致、衝突、失敗、保存対象の未処理と、検証の一致、欠損、不一致、読取不能、未解決を混同しない。正常完了以外ではコピー元を保持すべきことを明示し、詳細ログへ到達できるようにする。進捗通知のデータ形式や画面上の表現はプラン実行時に設計する。

### 5. 既存の安全性を弱めない

GUI経由でも、既存ファイルの無断上書き、コピー元の自動削除、削除同期、失敗の成功扱いを行わない。多重操作によって同じ取り込みが同時実行されないようにする。実行中の終了、再実行、エラー復旧の具体的な挙動は、既存の中断・再実行保証を確認したうえで実装時に決定する。

### 6. macOSアプリを再構築可能にする

PySide6の公式デプロイ手段を利用し、FinderまたはDockから起動できる`.app`を構築する。PythonとQtをアプリへ含める範囲、署名方法、成果物の配置は実装時に決める。

`ssh`、`rsync`、ExifToolなど既存の外部コマンドと、プロファイル、ホスト設定は現在の再構築方針を維持する。Finderから起動したアプリがシェルと同じ環境変数を持つことを前提にせず、必要な外部コマンドと設定を確実に発見できることを実機で確認する。

セットアップ、`.app`の構築または更新、環境検査を`scripts/mac/`から再実行できるようにし、利用手順を`docs/setup/mac.md`へ反映する。公開配布やMac App Storeへの登録は対象外とする。

## 対象範囲

- PySide6を使ったmacOS向けコピーGUI
- 既定の日常プロファイルによるワンクリック実行
- 実行前状態、処理中、完了、例外、実行不能の表示
- コピー処理とコピー後検証の進捗表示
- コピー結果と検証結果の要約表示
- 詳細ログを確認する導線
- 同時実行の防止
- CLIとGUIで共有するアプリケーション処理の整理
- GUI層と共通処理層の自動テスト
- FinderまたはDockから起動できるmacOS `.app`の構築
- GUI環境のセットアップ・構築・検査スクリプト
- `docs/setup/mac.md`と関連する正本の更新
- 実機Macでの通常経路、例外、再実行の確認

## 範囲外

- GUI上でのプロファイル、ホスト設定、保存先の汎用編集
- 写真・動画のサムネイル表示、選別、現像
- コピー元の削除、SDカードの初期化
- 主HDD上のファイル移動、改名、削除
- Amazon Photos、第2 HDD、Immichのバックアップ状態を統合した管理画面
- バックアップの自動実行と通知（0015）
- HTTPサーバー、認証、ジョブDB、常駐サービス
- macOS以外へのGUI配布
- Mac App Storeでの配布、第三者向けの署名・公証・インストーラー提供
- コピーや検証そのものの性能改善

## 実施手順

細かな設計判断と実機結果は、実施中に`decisions.md`と`validation.md`へ記録する。

### 段階1: 現状調査と詳細設計を行う

- [ ] 現在の共通API、CLI、プロファイル、ログ生成の責務を確認し、GUIと共有する境界を決める。
- [ ] 実機のPython、PySide6、macOS、外部コマンドの互換性を確認する。
- [ ] ワンクリック操作、進捗、結果、例外時の最小画面を設計する。
- [ ] バックグラウンド実行、同時実行防止、実行中終了の扱いを決める。
- [ ] `.app`の構築、更新、外部設定と外部コマンドの参照方法を決める。

### 段階2: 共通アプリケーション処理を整える

- [ ] CLIに残る共通処理を、CLIとGUIの双方から利用できるAPIへ分離する。
- [ ] コピーと検証の進捗を通知できるようにする。
- [ ] CLIの既存動作とJSONログの互換性を自動テストで確認する。

### 段階3: GUIを実装する

- [ ] 既定の日常プロファイルをワンクリックで実行できる画面を実装する。
- [ ] 実行中も画面の応答を保ち、処理の工程と進行を表示する。
- [ ] 正常完了、要確認、実行不能を区別し、コピー結果と検証結果を表示する。
- [ ] 多重実行を防ぎ、詳細ログを確認できるようにする。
- [ ] GUIを実データや実接続先に依存せずテストできるようにする。

### 段階4: macOSアプリと再構築手順を整備する

- [ ] PySide6をGUI用依存として分離する。
- [ ] `.app`を再構築するスクリプトを実装し、dry-runまたは同等の事前確認を備える。
- [ ] GUIと外部コマンド・設定を検査するスクリプトを実装する。
- [ ] `docs/setup/mac.md`へ導入、更新、起動、問題調査の手順を反映する。

### 段階5: 実機で検証する

- [ ] FinderまたはDockから`.app`を起動できることを確認する。
- [ ] 通常のSDから主HDDへの経路をGUIから実行し、コピーと検証が完了することを確認する。
- [ ] 数分間の処理中も実行中であることが分かり、画面が操作不能にならないことを確認する。
- [ ] 接続失敗、衝突、未処理、検証不一致などの代表的な例外を隔離した試験条件で確認する。
- [ ] 中断後または完了後の再実行でも、内容一致だけをスキップし既存ファイルを上書きしないことを確認する。
- [ ] CLIとGUIで、同じ条件の結果判定とログ内容が一致することを確認する。
- [ ] セットアップ・構築・検査スクリプトを実機で実行し、新しいMacで再構築できる手順になっていることを確認する。

## 完了条件

- FinderまたはDockからmacOSアプリを起動し、既定の日常取り込みをワンクリックで開始できる。
- 実行中に現在の工程と進行が表示され、GUIが無応答にならない。
- コピー結果と検証結果について、正常完了、要確認、実行不能を利用者が区別できる。
- 正常完了以外ではコピー元を保持すべきことが明示され、詳細ログを確認できる。
- CLIとGUIが同じ共通処理を使い、結果判定とJSONログの意味が一致する。
- GUIから既存ファイルの無断上書き、コピー元削除、削除同期を実行できない。
- 同じ取り込みの多重実行を防止できる。
- GUIと共通処理の自動テスト、および既存のCLIテストが成功する。
- `.app`の構築と環境検査がスクリプト化され、実機で確認済みである。
- `docs/setup/mac.md`から新しいMacへの導入、アプリ構築、日常起動、問題調査を再現できる。
