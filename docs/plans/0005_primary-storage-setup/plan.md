# 0005: 主HDDとSMB共有の整備

作成日: 2026-09-11  
更新日: 2026-09-11  
状態: 完了

## 目的

Ubuntuに常時接続する4TB主HDDを写真・動画の正本として安全に利用できるようにする。MacからSMB経由でアクセスでき、未マウント時にローカルSSDへ誤って保存しない状態にする。あわせて、この作業を新しいPCで再現するための仕組みを用意する。

## 対象範囲

- 主HDDを `/mnt/camera_archive` に固定マウントする。
- 写真・動画の保存用ディレクトリと、コピーに必要な権限を設定する。
- MacからSMBで接続し、読み書きできることを確認する。
- 未マウント時にコピー先として使用できないことを確認する。
- 上記の作業をスクリプト化し、`docs/setup/` と `scripts/` の初期構成を用意する。

Immichの導入、実データの本格的な取り込み、第2 HDDへのバックアップはこのプランの対象外とする。Mac側の手順書は入口だけ作り、内容は0006以降で埋める。

## 前提

- 主HDDはUbuntuに常時接続する4TB HDDである。
- 正本のルートは `/mnt/camera_archive` のみとする。
- Macからの通常の取り込みは、SDカードからSMB経由でこのルートへコピーする。
- SMBの共有範囲は写真ライブラリに限定し、Immichには後続プランで読み取り専用として提供する。
- 再構築性の方針は [proposal.md](../../proposal.md) の「環境構築の再現性」に従う。

## 実施手順

作業は手作業で進めてから清書するのではなく、スクリプトを書いて実行する。実機で実行していないスクリプトは完成として扱わない。

- [x] 主HDDのデバイス、ファイルシステム、UUID、容量を確認する。
- [x] `scripts/` と `docs/setup/` の初期構成を作り、実行規約とホスト固有値の渡し方を決める。
- [x] `/mnt/camera_archive` への固定マウントをスクリプトで設定し、再起動後も同じパスで利用できることを確認する。
- [x] マウント先の所有者・権限をスクリプトで設定し、写真保存用のアカウントだけが書き込めるようにする。
- [x] Samba共有をスクリプトで設定し、Macから固定の共有名で接続できることを確認する。
- [x] Macからテストファイルを作成・読み出し・削除し、Ubuntu側でも結果を確認する。
- [x] 主HDDを安全にアンマウントした状態で、`/mnt/camera_archive` へ書き込めないことを確認する。確認後は再マウントする。
- [x] 完了条件を判定する確認用スクリプトを用意し、実行結果を記録する。
- [x] ホスト固有値を `scripts/hosts/*.env` に、自動化できない操作と実行順を `docs/setup/ubuntu.md` に反映する。
- [x] 実際のマウント情報、共有名、利用アカウント、確認結果を `validation.md` に記録する。

## 完了条件

- 主HDDが再起動後も `/mnt/camera_archive` にマウントされる。
- MacからSMB経由で写真ライブラリへ読み書きできる。
- 主HDDが未マウントの場合、コピー先として利用できず、SSDへの誤書き込みを防げる。
- 設定値と確認結果が記録され、0006のコピーCLIから保存先として利用できる。
- `docs/setup/ubuntu.md` と `scripts/` だけを使って、同じ構成を新しいUbuntu環境で組み直せる状態になっている。スクリプトは冪等で、再実行しても既存の設定とデータを壊さない。
- 確認用スクリプトで完了状態を判定できる。
