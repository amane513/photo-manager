# 0018: コピー経路と導入ロードマップの見直し

作成日: 2026-09-05

状態: 完了（文書改訂のみ。CLI実装・実機検証・実データ移行は未実施）

## 後続改訂

本書は最初の改訂時点の判断記録である。HDDの作業領域分離、保存確定、イベント配置、選別・現像を前提とした導入順は [0021](../0021_simplify-photo-workflow/plan.md) で廃止・変更した。現在の運用判断には正本と最新ロードマップを使用する。

## 目的

Amazon Photosの対象を主HDDへ変更し、SD→HDDとSD→Mac→HDDの両経路を使える、簡素な運用へ改訂する。初期動作確認からコピーをCLIで自動化し、将来GUIから呼べる共通処理APIを設計する。

- 進行中の0003の残作業・完了条件の更新。実施済み記録は保持する。
- 従来の進め方のレビューと、新しい依存関係の定義。

既存の0001〜0017を維持し、本改訂は0018、最小CLIは0019、GUIは0020とする。実データの移動、アプリ設定の切替、CLI実装はこの変更に含めない。

## 採用判断

1. AmazonはMacからSMBで主HDDの保存確定先を参照する。バックアップ可能なことはユーザー確認済みとし、未検証の形式・再取得・再接続とは区別する。
2. 経路aを基本とし、Mac内のコピーを省く。SDカードはMacに挿し、SMB経由でHDDへコピーする（ユーザー確認済み）。
3. Macは `PhotoWork/` の1ルートとし、取り込み時からHDDと同じ年月・イベント・機器別構成にする。
4. HDDでは `photo-incoming/` と `photo-library/` を分け、Amazon・Immich・通常バックアップは後者だけを見る。未選別データをHDDへ一時コピーできるよう要件を明確化する。
5. HDD直行時はMacからSMB上で選別・現像する。これが扱いにくい場合に経路bを使う。保存確定後は原則として整理・編集しない。
6. 0019でコピーと配置・保存確定を先行する。0010は欠損・内容一致の検証へ絞り、初版の動作確認を妨げない。
7. API志向は共通処理とUIの分離から始める。HTTPサーバーやジョブ管理基盤はGUIの形態が決まるまで必須にしない。

Macの2ルートを単純に消し、未選別ファイルをAmazon対象へ直接入れる案は、不採用データをバックアップしない既存要件に合わない。作業と公開の境界をHDDへ置くことで、その要件とMac内の簡素化を両立する。

## 最小CLIの範囲と検証の線引き

| 初期から必要 | 後から追加できる |
|---|---|
| 対象列挙、明示的な分類先、フォルダ作成、コピー、保存確定 | 撮影日時の自動分類、一括リネーム |
| dry-run、上書き禁止、元データ保持、マウント確認 | 全件チェックサム、ペア欠損検出 |
| I/Oエラー通知、途中ファイル隔離、実行結果一覧 | 内容確認による既存ファイルのスキップ・自動再開 |
| 共通API、構造化結果・進捗、CLI | GUI、必要に応じたHTTP、常駐・定期実行 |

初期CLIでも衝突やエラーを無視して成功にしない。一方でコピー後の内容一致は未検証と表示できればよく、チェックサム基盤が完成するまでコピー機能を止めない。最初の受入確認は小さなファイル群で、両経路の同一配置、同名衝突時の非上書き、コピー元保持、接続切れ時の失敗、途中データの非公開を確認する。

## 未確定事項・後続確認

- 経路aのSD接続先はMacと確定した。Ubuntu側へのSD直接接続は今回の対象外とする。
- SMB上の現像・XMP保存の操作性は0003で確認する。
- Amazonの再接続・動画除外・対象切替時の重複は0004で確認する。バックアップ可否の確認済みという報告から、これらまで合格とは推定しない。
- 既存Mac作業フォルダの実ファイル移行は、残存データとAmazon設定を確認してから別途実施する。
