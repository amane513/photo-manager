# 写真・動画管理環境 要件

## 1. 目的

カメラとスマートフォンで撮影した写真・動画を、安全に管理・バックアップし、見やすく閲覧できる環境を構築する。

主な用途は子供の写真・動画の保管と閲覧である。

## 2. 対象データと撮影機器

- カメラはSony α7C IIを使用する。
- スマートフォンはiPhone 13を使用する。
- カメラで撮影したJPEGとRAWの両方を保存する。
- iPhone 13で撮影した写真と動画も保存する。

## 3. 取り込み・選別・現像

- 煩雑な運用に時間をかけないことを優先する。反復作業は自動化し、不要データの残存や保存先ごとの差異は許容する。
- Macに挿したSDカードから、Mac内へ保存せずSMB経由でUbuntuの主HDDへコピーする経路を基本とする。
- 必要時にはSDカードからMacへ取り込み、その後主HDDへコピーする経路も使えるようにする。
- HDD直行時は原則として選別しない。Mac経由でも選別・現像は任意とする。
- Macへ取り込む時点からHDDと同じ年月・機器別の相対フォルダ構成にする。イベントフォルダは設けない。
- Macの作業フォルダは1つとし、HDD内も作業領域と正本に分けない。コピー後の保存確定操作は設けない。
- 基本的にはカメラの撮って出しJPEGを利用し、必要な場合だけMacでRAWを現像する。HDDへの保存後に現像済みJPEGを追加してもよい。
- HDD上の不要な写真・動画は後から削除できる。削除履歴の厳密な管理は求めず、コピー元から再取り込みされることも許容する。

## 4. 保存・バックアップ

- Ubuntuに接続した4TB主HDDを写真・動画の正本とし、第2 HDDとAmazon Photosへバックアップする。
- Amazon Photosの対象はUbuntuの主HDD上の写真とする。MacからSMB接続した共有を公式Macアプリでバックアップする。SMB経由でバックアップできることはユーザー確認済みである。
- Amazon Photosには写真だけを保存し、動画は保存しない。JPEGとRAWはどちらも保存する。
- 不要な写真がバックアップ先に残ることや、HDDで削除した写真がAmazon Photosにだけ残ることを許容する。保存先同士の完全一致や削除の伝播は求めない。
- バックアップは取り込みとは別に進め、取り込みのたびに全保存先の完了を待つ運用にしない。次のバックアップまで保護が薄い期間を許容する。
- 取り込み完了、バックアップ完了、コピー元を削除できる状態は区別する。

## 5. 閲覧環境

- 常時稼働するUbuntuデスクトップPC上にImmichサーバーを構築する。
- Amazon PhotosではJPEGとRAWが両方表示され、同じ写真が重複して見えるため、Immichでは見やすく閲覧できるようにする。
- Immichの閲覧以外の機能についても、利用を検討する。

## 6. 家族との共有

- 現在は祖父母向けに「みてね」で写真と動画を公開している。
- 利便性が向上し、祖父母の移行負担に見合う場合は、別の共有方法への乗り換えも選択肢とする。

## 7. 操作と段階導入

- 初期の動作確認から、コピーとフォルダ作成・配置をCLIで自動化する。
- 通常は撮影年月を自動判定し、同一と確認できた既存ファイルはスキップする。最小コピー機能を先行し、これらを直後の改善として導入する。
- 結果の要約と詳細ログを自動生成し、人は失敗・衝突・未処理などの例外に対応する。日常の全件目視や手書き転記は求めない。
- 全件の欠損・内容一致検証はコピー機能から分離し、後から導入できるようにする。
- 将来は同じ処理をGUIから操作できるようにする。処理の中核をCLIから分離し、共通APIとして利用できる設計とする。
- 既存ファイルの無断上書き、失敗の成功扱い、コピー元の自動削除は行わない。
- 初期検証ではコピー元を保持する。日常運用のコピー元削除は、コピー内容とバックアップを確認する別の判断とする。
