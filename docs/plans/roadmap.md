# プランロードマップ

このファイルでは、実施済み・進行中のプランと、[proposal.md](../proposal.md) を実現するための今後のプランを管理する。

更新日: 2026-09-11。最新の方針変更は [0004](0004_simplify-photo-workflow/plan.md)、当初の見直しとレビューは [0003](0003_workflow-roadmap-revision/plan.md) を参照する。

## 番号とフェーズの扱い

- プラン番号は推奨する着手順を表す。番号が小さいものから進める。
- 番号は0001から連番とし、欠番を作らない。新規プランは末尾に採番する（現時点では0022以降）。
- 推奨順が変わった場合は、ロードマップ全体を再採番し、フォルダ名と参照も合わせて更新する。
- フェーズは作業のまとまりを示す。同一フェーズ内は番号順を基本とし、並行できる箇所は[推奨する着手順](#推奨する着手順)に示す。
- 未着手プランのフォルダと `plan.md` は着手時に作成する。

## 全体像

```text
フェーズ0  方針整理           0001 0002 0003 0004
              │
フェーズ1  基盤整備           0005 主HDD・SMB ─> 0006 コピーCLI
              │
フェーズ2  取り込み運用の確立  0007 配置・閲覧 ─> 0008 Amazon ─> 0009 両経路の通し確認
              │
フェーズ3  保全と閲覧基盤      0010 バックアップ ─> 0011 Immich導入 ─> 0012 表示・DB復元
              │
フェーズ4  運用の拡張         0013 全件検証    0014 GUI
              │
フェーズ5  条件付き           0015〜0021（必要性が生じたときに判断する）
```

## フェーズ1: 基盤整備

写真の保存先とコピー手段を用意する。ここが終わるまで実データの本格的な取り込みは始めない。

| ID | 予定フォルダ | 概要・完了の目安 | 前提 |
|---|---|---|---|
| 0005 | `0005_primary-storage-setup` | 主HDDの固定マウント・権限・SMBを整備する。正本は1ルートとし、未マウント時の誤書込みを防ぐ。既存の確認済み構成を再利用する | 0002 |
| 0006 | `0006_copy-cli-foundation` | 最小版でSD→HDD、SD→Mac、Mac→HDDの配置付きコピー、基本的な保護、結果要約・ログを用意する。直後に年月の自動分類と内容一致に基づく同名スキップを追加する | ローカル実装は0004。SMB受入確認は0005 |

### 0006の段階分け

1. **最小版**: コピー・フォルダ作成・明示年月での配置、dry-run、無断上書き禁止、コピー元保持、マウント確認、一時ファイル処理、構造化結果とログを実装する。この時点で初期動作確認を開始する。
2. **直後の改善**: 撮影年月の自動分類、日時不明の報告、同名候補の内容比較とスキップ、部分失敗後の再実行、定型設定の再利用を追加する。Mac→HDDは既存の相対配置を維持する。

CLIは共通処理APIを呼ぶ。保存確定、イベント指定、HTTPサーバー、全件チェックサム、削除履歴管理は0006の範囲に入れない。同名候補の内容比較は日常の再実行を楽にするため前倒しし、全件のコピー後検証とは分ける。

SDはMacに接続する。iPhoneの機器からの取得はイメージキャプチャを使い、その後の配置に共通処理を使う。

## 推奨する着手順

番号順が基本だが、次の並行関係を使って待ち時間を減らせる。

```text
0002 ─> 0005 主HDD・SMB ────────────────────┐
0004 ─> 0006 最小CLI（ローカル先行）──────────┴─> 初期動作確認
         │                                      ├─> 0007 基本確認 ─┐
         └─> 自動年月分類・同名スキップ ──────────┼─────────────────┼─> 0009 両経路確認
                                                └─> 0008 Amazon ──┘
0002 + 0005 ─> 0010 バックアップ・原本復元 ─> 0011 Immich ─> 0012 表示・DB復元
0006 最小版 ─> 0013 全件検証
0006 + 0009 ─> 0014 GUI
0007 選別・現像 ─> 必要になったときに確認（上記工程の前提にしない）
```

## 検証と日常運用

- 初期確認は各形式1〜2組を目安とし、形式・操作・例外を代表するケースで行う。一律10組や1か月の手動運用を必須にしない。
- 0006では正常コピー、異なる同名、同一スキップ、複数月、日時不明、切断、再実行を確認する。各後続プランは結果を再利用する。
- 日常はCLI実行と要約確認で終える。失敗・衝突・未処理だけ対応し、詳細ログは自動保存する。代表ファイルを毎回開いたり、全件の件数を手書きしたりしない。
- Amazon確認と第2 HDDバックアップは原則週次にまとめる。復元試験は導入時・変更時・定期確認に行う。
- コピー元の削除は別操作とする。0009・0010で主HDDの内容確認、第2 HDD保存、必要に応じたAmazon完了の確認方法を定める。検証導入前の確認結果は簡潔に記録し、試験中はコピー元を保持する。
