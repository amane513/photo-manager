# アーキテクチャ

この文書は、複数の機能にまたがる実装構造と安全性の境界を記述する。外部から見える振る舞いは [`specification/`](specification/) を正本とする。

## モジュール構成

| モジュール | 主な責務 |
|---|---|
| `cli.py` | 引数解析、設定上書き、例外から終了コードへの変換 |
| `config.py` | INI設定の読み込み、検証、CLI上書きとの統合 |
| `volumes.py` | Volume UUID、マウントポイント、容量、書込可否、hard linkの事前確認 |
| `locking.py` | import / verify / mirror間のOSレベル排他制御 |
| `discovery.py` | SDカード上の対象列挙、除外、MP4/XML対応付け |
| `metadata.py` | exiftoolとXMLからの撮影日時決定 |
| `naming.py` | 相対宛先、重複、別名候補を含む転送計画 |
| `transfer.py` | 一時ファイルへのコピー、ハッシュ、再読込検証、正式化 |
| `ledger.py` | 台帳の厳密な読取り、追記、補完、修復、置換 |
| `importer.py` | importの処理順、集計、台帳完全性、eject可否 |
| `verify.py` | 台帳と管理対象ツリーの双方向照合 |
| `mirror.py` | コピー元検証、非破壊同期、コピー先検証、台帳公開 |
| `runtime.py` | シグナル、中断、実行中資源の解放 |
| `logging_utils.py` | 実行ログと表示レベル |

`scripts/photo-*` はリポジトリの `src/` を解決し、共通CLI層へ引数を渡す薄いエントリーポイントとする。安全性に関わる処理を各スクリプトへ重複実装しない。

## 処理の境界

処理は概念的に次の層へ分ける。

| 層 | 責務 |
|---|---|
| CLI | 入力の解析と終了コードへの変換 |
| 読み取り専用事前チェック | 設定、パス、UUID、依存、台帳構文、暫定計画、容量の検査 |
| 計画作成 | 対象列挙、日時、宛先、衝突、必要容量の決定 |
| ロック後再確認 | 外部状態の変化を考慮したauthoritativeな再計画 |
| 実行 | 一時コピー、検証、正式化、台帳更新 |
| 最終検証 | 台帳と正式ファイル、ejectまたは台帳公開条件の確認 |
| 表示・ログ | 進捗、集計、警告、失敗、終了結果 |

dry-runと実行時は同じ計画作成ロジックを使う。永続的変更はdry-runの分岐より後ろに置く。実行時はロック後に計画・衝突・容量を再確認し、その結果だけを変更の根拠にする。

## 構造化された状態

主要な入力・計画・結果は `dataclass` と `enum` で表現する。

- `Config`: 宛先、UUID、ソース、ミラー先、外部ツール、オプション
- `SourceFile`: 元パス、種別、サイズ、mtime、対応MP4/XML
- `CaptureTime`: 日時、取得方法、警告
- `TransferPlan`: 元ファイル、相対宛先、処理予定、検証済み情報
- `TransferResult`: copied / skipped / conflict / failed とdigest・警告
- `LedgerRecord`: path / algorithm / digest / size / captured_at / imported_at
- `RunSummary`: コピー、スキップ、警告、失敗、台帳有効性、eject可否

最終的な成功条件やeject判定をログ文字列から推測せず、構造化結果から決定する。

## macOSとの連携

- Volume情報は `/usr/sbin/diskutil info -plist <path>` のバイト列を `plistlib.loads()` で解析し、ロケール依存テキストを判定に使わない。
- eject対象にはパーティションの `DeviceIdentifier` ではなく `ParentWholeDisk` を使用し、実行直前にマウントポイントを再確認する。
- importとmirrorは `LOCK_EX | LOCK_NB`、verifyは `LOCK_SH | LOCK_NB` を使用する。mirrorで2ボリュームを取る場合は一定順序で取得する。
- 永続化ではmacOSの `F_FULLFSYNC` を試し、利用できない場合だけ `os.fsync` へフォールバックしてログへ記録する。正式化後は親ディレクトリも同期する。
- 再読込ハッシュでは読み取りfdへ `F_NOCACHE` を設定し、直前のページキャッシュを避ける努力をする。これは媒体上のビットに関する完全な保証ではないが、通常のキャッシュ読取りより強い検証境界を作る。

## 公開と永続化の不変条件

1. 一時ファイルは `<archive>/_photo-manager/tmp/` だけに作る。管理対象メディアツリーには未完成ファイルを見せない。
2. 一時ファイルは排他的に新規作成し、同名の残骸を上書きしない。
3. 元のdigestと再読込digest、および元ファイルの不変性を確認してから正式化する。
4. 正式化には同一ボリューム内の `os.link` を使う。宛先が存在すれば失敗する性質により置換を構造的に防ぐ。
5. hard link作成後の一時ファイルunlink失敗は、正式ファイルの公開を巻き戻さない。警告として構造化し、資源解放時に掃除を再試行する。
6. データ台帳は正式化後に更新する。正式化後の台帳失敗でデータを削除しない。
7. 台帳そのものは管理ファイルなので、検証済み一時ファイルからのアトミック置換を許可する。
8. 管理ファイルの置換後は成否を推測した削除を行わない。

一時ファイルを管理領域へ隔離する判断の詳細は [ADR 0003](decisions/0003-managed-part-location.md) を参照する。

## エラーと中断

使用方法・設定・状態変更前の事前チェックエラーと、ファイル単位または実行中の操作失敗を型で区別する。SIGINT / SIGTERMは専用の中断として伝播させ、広い操作エラーのハンドラでファイル単位失敗へ変換しない。

実行中に作成したfd、ロック、一時ファイルなどは実行資源として追跡し、成功・失敗・中断のすべてで解放する。ただし正式公開済みのデータや、アトミック置換後の管理ファイルを「片付け」の名目で削除してはならない。

## テスト方針

- ファイル操作は一時ディレクトリへ隔離し、小さな実ファイルでコピーとハッシュ経路を通す。
- exiftool、diskutil、ejectは境界で差し替え、入力形式と呼出引数を検証する。
- 時刻、UUID、外部コマンドrunnerを注入可能にして決定的なテストにする。
- 正常系だけでなく、各永続化境界の直前・直後、競合、中断、再実行を検証する。
- importの結合テストでは discovery → metadata → naming → transfer → ledger を通す。
- 安全性の中心である「上書きしない」「検証前に公開しない」「失敗時にejectしない」を個別の回帰テストで固定する。
