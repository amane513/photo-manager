# 0002: ストレージ容量調査

作成日: 2026-08-23  
状態: 完了

## 目的

- 現在保有する写真・動画の総容量と内訳を把握する。
- カメラ購入直後で将来の撮影量を予測できないことを前提に、初期導入時点の容量判断を行う。
- Ubuntu PCとMacBook Airで、運用に使える空き容量を確認する。
- 主HDDのバックアップと将来の増加を無理なく収められる第2 HDDの必要容量を決める。

## 対象範囲

- 現在の写真・動画が置かれているMacBook Air、既存HDD、SDカード等の保存場所の容量調査
- Sony α7C IIのRAW（ARW）、JPEG、XMP、iPhoneのHEIC、Live PhotoのMOV、通常動画、現像済みJPEGの内訳調査
- 既存データ量と、初回の実運用で得られる容量実績の記録
- Ubuntu PCの内蔵SSD空き容量、接続予定の4TB主HDDの実容量・空き容量の確認
- 第2 HDDの推奨容量と購入・利用判断の記録

このプランではデータの移動、削除、Immichの導入、バックアップの実施は行わない。第2 HDDへのバックアップ方式の確定は [0007_backup-workflow](../future_plans.md) で行う。

## 前提

- 主HDDはUbuntuへ常時接続する4TB HDDとする。
- 第2 HDDは、主HDDの原本、ImmichのDBダンプ、設定ファイルを保存するため、通常は取り外して運用する。
- 初期の第2 HDDバックアップは削除を伝播しない追加コピーを想定する。
- MacBook Airは一時作業場所であり、常時の正本保管場所にはしない。
- α7C IIは購入直後のため、過去のデータから年間増加量を推定しない。撮影量の実績が得られた後に容量計画を見直す。

## 測定方法

### 1. 調査対象を確定する

- 写真・動画が存在する保存先を列挙する。Macの写真ライブラリ、Finder上のフォルダ、既存の外付けHDD、カメラのSDカード、iPhone内の未取り込みデータを含める。
- 同じデータの複製は区別して記録し、総量の集計では重複を除いた「ユニークな原本・派生物」の容量を求める。
- 保存先ごとに、調査日時、ファイル数、使用量、空き容量、読み取り可否を記録する。

### 2. 写真・動画の容量と内訳を測る

- 各保存先について、対象フォルダまたはライブラリの合計バイト数とファイル数を取得する。
- 次の分類ごとにファイル数と合計容量を集計する。

| 分類 | 主な拡張子 | 扱い |
|---|---|---|
| カメラRAW | `.ARW` | 正本・第2 HDD・Amazon Photosへ保存予定 |
| カメラJPEG | `.JPG`, `.JPEG` | 正本・第2 HDD・Amazon Photosへ保存予定 |
| 現像設定 | `.xmp` | RAWと対応付けて正本・第2 HDDへ保存予定 |
| iPhone写真 | `.HEIC`, `.HEIF` | 正本・第2 HDD・Amazon Photosへ保存予定 |
| Live Photo動画 | `.MOV` | 正本・第2 HDDへ保存予定 |
| 通常動画 | `.MOV`, `.MP4`, `.M4V` など | 正本・第2 HDDへ保存予定 |
| 現像済みJPEG | `edited/` 配下の `.JPG`, `.JPEG` | 正本・第2 HDD・Amazon Photosへ保存予定 |
| その他 | 上記以外の関連形式 | 用途を確認して個別に扱いを決める |

- `.MOV` はLive Photo由来と通常動画を可能な範囲で分ける。ファイル名・撮影日時だけでは判定できない場合、合計は動画として記録し、検証時に少数サンプルで組を確認する。
- macOSのFinder表示、`du`、`find` 等の結果に差がある場合は、論理サイズかディスク使用量かを明記し、容量計画にはファイルの論理サイズを使用する。

### 3. 初回運用の基準値を残す

- 現在の既存データ量を、初期導入時点の基準値として記録する。
- 初回の取り込み後に、RAW、JPEG、HEIC、動画、現像済みJPEGの増分を記録する。ただし、単発の取り込み結果を年間増加量へ換算しない。
- 新しいカメラを含む実運用を最低1年続けた後、または主HDDの使用率が60%に達した時点で、実測値を基に容量計画を改めて見直す。

### 4. 運用先の空き容量を確認する

- Ubuntu内蔵SSDについて、OS、Docker、Immich DB、サムネイル、変換済み動画を置く予定のボリュームの総容量、使用量、空き容量を確認する。
- 4TB主HDDについて、実際に利用可能な容量、現在の使用量、空き容量、ファイルシステムを確認する。
- MacBook Airについて、`PhotoInbox/current/` と `ReadyForArchive/` を一時的に置ける空き容量を確認する。
- 容量はGB/TB表記の基準（10進または2進）を記録し、比較時には同じ基準へそろえる。

## 判断基準

第2 HDDの必要容量は、次の値を合算して決める。

```text
第2 HDDの初期必要容量 = 主HDDの実容量
                      + Immich DBダンプ・設定の見込み量
                      + 運用余裕
```

- 第2 HDDは主HDD全体をバックアップできる必要があるため、主HDDと同じ4TB以上を必須とする。
- 年間増加量を予測しないため、初期の推奨容量は主HDDより一段階大きい8TBとする。これにより、主HDDの4TBを使い切る場合でも、DBダンプ、設定、追加コピー時の一時的な重複に対応できる。
- 将来、削除履歴を保存する方式を採用する場合、または主HDDの使用率が60%に達した場合は、第2 HDD容量とバックアップ方式を0007で再評価する。
- 市販容量・価格の比較は購入時点で行い、このプランでは特定製品や価格を固定しない。
- 主HDDの使用率は、初期導入時点で80%未満を目標とする。80%を超える見込みなら、主HDDの増設・交換も 0005 着手前に検討する。

この決定は将来の撮影量を予測したものではなく、4TB主HDDを安全にバックアップするための初期構成である。

## 記録する結果

調査完了時に、このフォルダへ `assessment.md` を追加し、少なくとも次を記録する。

- 調査日時と対象保存先
- 保存先別の総容量、ファイル数、空き容量
- データ種別別のファイル数・容量・全体に占める比率
- 重複として除外したデータと除外方法
- 初回取り込みのデータ種別ごとの増分と、容量計画の見直し条件
- Ubuntu内蔵SSD、主HDD、MacBook Airの容量判定
- 主HDD容量を基準にした第2 HDDの必要容量と判断根拠
- 第2 HDDの推奨容量、採用理由、将来の見直し条件
