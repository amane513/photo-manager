### dry-run

`photo-copy copy --profile sd-to-ubuntu --dry-run` を実行した（ログ: `copy-20260913-091715-431065.json`）。要約は、予定962件、既存内容一致スキップ43件、衝突0件、失敗0件、未処理10件、除外7件であった。実運用規模でも要約だけで例外の有無と件数を把握できる。

未処理10件は `AVF_INFO` の `.BNP`・`.INP`・`.INT`、`PRIVATE/DATABASE/DATABASE.BIN`、動画に付随する `.XML`、`MEDIAPRO.XML` であり、いずれもSonyの管理情報である。保存対象のARW、JPEG、MP4は未処理になっていない。除外7件は `.fseventsd` と `._*` のmacOS補助ファイルである。

### 本実行と再開

`photo-copy copy --profile sd-to-ubuntu --log-dir docs/plans/0009_routine-import-operation` を実行した。

- 最初の実行は127件のコピー後、SSH接続のbroken pipeにより中断した（ログ: `copy-20260913-091910-643432.json`）。コピー元は変更されず、既存ファイルも上書きされなかった。
- 同じコマンドを再実行し、残りを安全に再開した。835件をコピー、170件を内容一致でスキップし、衝突・失敗は0件で完了した（ログ: `copy-20260913-092604-420614.json`）。この170件は、先行実行でコピー済みの127件と開始時からの既存43件である。
- したがって、今回新規に主HDDへ保存した件数は962件である。開始時の既存一致43件を含め、保存対象1,005件はすべて主HDDに存在する。
- 最初のログの完了時刻は09:19:10、再開後のログの完了時刻は09:26:04であり、中断から再開を含む一括取り込みは約7分で完了した。1ファイルごとにrsyncを起動する実装でも、27 GB・1,005件のカードを無操作で取り込めるため、日常の取り込み時間として許容する。

日常運用で同じ例外が出た場合は、詳細ログで中断理由を確認し、SSH接続・主HDDの状態を直して同じプロファイルのコマンドを再実行する。一時ファイルや部分コピーを手作業で確定・削除しない。内容一致が確認できたものだけがスキップされ、異なる内容の既存ファイルは衝突として停止する。

### 内容一致スキップの再確認

同じコマンドをもう一度実行した（ログ: `copy-20260913-093132-195507.json`）。コピー済み0件、スキップ1,005件、衝突0件、失敗0件、未処理10件、除外7件であった。ログの完了時刻は09:31:32であり、再実行の所要時間は約5分半であった。

再実行ではデータ転送を行わず、Mac側とリモート側でサイズとSHA-256を比較するため、1,005件・27 GBでは「即時」には終わらない。通常運用は再実行を必須にせず、失敗・中断の復旧時だけ実行するため、現状は性能改善を行わない。GUI（0014）では、再実行時に数分を要しうることを進捗表示の前提とする。今後、同規模以上のカードで日常作業を妨げる場合は、ファイル単位のリモートハッシュとrsync起動をまとめる改善を別プランとして起票する。
